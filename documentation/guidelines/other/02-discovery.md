# 2. Understand users and define scope

1. Describe the problem, intended users, desired outcomes and constraints. Separate verified facts from assumptions and identify how to validate important assumptions.
2. Create a small set of representative user profiles when they clarify differing goals, contexts or accessibility needs. Avoid inventing unsupported personal details.
3. Write scenarios for important tasks and exceptions. From these, derive concise user stories describing a role, goal and benefit.
4. Turn needs into individually identifiable functional and nonfunctional requirements. Make each necessary, clear, testable and traceable; specify measurable targets where they matter. Record open questions rather than inventing targets.
5. Group stories into features. For each important feature describe its trigger, inputs, behavior, outputs, errors and permissions. Check that it serves a real user need and that dependencies are explicit.
6. Prioritize a feasible minimum product and identify deferred work. Define acceptance criteria and connect each core requirement to stories and future verification.

**Output:** problem statement, user profiles or assumptions, scenarios, prioritized stories, requirements and feature list. Review with stakeholders and revise as evidence changes.
