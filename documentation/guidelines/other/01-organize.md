# 1. Organize the work

1. Read the assignment or product brief, identify stakeholders, constraints, deadlines and required deliverables. Record ambiguities for the team to resolve.
2. Establish a shared repository and a project board. Break work into small outcomes, assign an owner where appropriate, track status and dependencies, and review progress regularly.
3. Agree on communication, review, branching, integration, and a definition of done. Include documentation, tests and accessibility in that definition when relevant.
4. Set up a documentation index and store editable source files for artifacts. Record decisions and changes, with dates and reasons when helpful.
5. Assess risks such as unfamiliar tools, external dependencies and limited time. Prioritize the riskiest assumptions for early validation.

**Output:** a short team plan, initial backlog, decision log and risk list. Revisit these throughout the project.
