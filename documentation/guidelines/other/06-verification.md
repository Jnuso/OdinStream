# 6. Verify and deliver

1. Check each core acceptance criterion against the implemented behavior. Exercise normal, invalid, boundary and failure cases, including access by different roles where relevant.
2. Run the documented setup, build, automated tests and a representative browser journey from a clean environment. Verify that data persists and that integration between components works.
3. Review security and privacy: authentication and authorization, validation, secret handling, dependency risks, safe errors and logging. Record limitations and resolve issues in proportion to their impact.
4. Review accessibility and usability, including keyboard access, labels, feedback and responsive layouts. Check the team’s relevant nonfunctional requirements.
5. Confirm the README describes prerequisites, configuration, startup, tests, service dependencies and troubleshooting. Update diagrams, API contracts and known limitations to match the actual system.
6. Prepare a repeatable demonstration using safe sample data. Record what was tested, results, remaining issues and any required AI-use disclosure. Release or deploy only when authorized and after applicable checks pass.

**Output:** acceptance evidence, test results, current documentation, known issues and a demonstration plan.
