# Odin Stream design references

## Desktop prototype

[Open the desktop prototype in Figma](https://www.figma.com/design/5XYePmMMFHpCiqM6MLm4su/Odin-Stream-%E2%80%94-Desktop-Screens--Prototype-). This is the team's selected desktop design direction. Figma is the editable source; the prototype illustrates interface ideas and interactions, not completed application functionality.

The desktop file includes Discover, movie and show details, search results, My Library and its states, Feed, Profile, New Post, and settings or confirmation dialogs. Use the individual frames to understand the intended layouts and flows.

## Mobile sketches

[Open the mobile sketches in Figma](https://www.figma.com/design/ma8S3CmWx675i5hsZFCk2k). These show the five main mobile areas: Discover, My Library, Feed, Profile, and Post. The team may refine mobile and desktop layouts as implementation progresses.

## Implementation guidance

- Use the designs as the visual and interaction starting point; review changes with the team and keep related user stories and acceptance criteria current.
- Prototype text, prices, titles, provider availability, accounts, and other sample data are illustrative; use actual application and TMDB data when implementing.
- The agreed MVP supports U.S. availability only, even where a design shows a country selector. Do not infer that TMDB supplies rental or purchase prices from mockup text.
- Implement accessible keyboard navigation, labels, focus, responsive layouts, and meaningful loading, empty, and error states, even where the prototype does not show them.
- The [MVP scope and decisions](../scope-and-decisions.md) and [user stories](../user-stories.md) record behavior and open decisions. Resolve conflicts with the team instead of assuming a prototype interaction is an approved requirement.
- Keep Figma links accessible to teammates, and update this guide when the design reference or a meaningful design decision changes.
